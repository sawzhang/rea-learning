# 第六轮：多场景覆盖率合并与分支对照

日期：2026-10-13。上游仍固定 REA 6.4.0 / `c22111eca2c4bc84a084f12711f405b3e7422a40`；本机 Node 26.10.0。

## 为什么不能直接合并 ranges

第五轮 baseline 的 choose 外层区间 count=1，非正数路径子区间 count=0；expanded 同样外层 count=1，但正数路径子区间 count=0。简单把外层计数加到子区间，会把 baseline 没执行的路径说成执行过。另一种错误是仅按完全相同的起止偏移配对：两个场景的零计数子区间不同，缺失同名区间不代表零计数，应继承该场景包含它的父区间。

`src/browser/execution/CdpPreciseCoverage.ts` 保留原始嵌套区间并声明 UTF-16/exclusive 边界；它是单次采集规范化，不是多场景合并器。`CdpRuntimeProtocol.ts` 定义各范围 count 与 isBlockCoverage。本轮合并逻辑放在学习项目，不改上游或声称 REA 自动支持此种 Node coverage 合并。

## 本项目的实现

`scripts/run-merge-lab.mjs` 重新调用第五轮真实采集器，验证正常退出后读取本次 report。第五轮已核对静态工件摘要、文件 URL、唯一 UTF-16 函数范围与原始 V8 记录，所以本轮使用相同 static_node_id 关联同一函数。

`scripts/merge-coverage.mjs`：

1. 要求 capture ID 唯一，源码 SHA-256、Node 版本、偏移单位一致。
2. 要求每个场景的指定函数集合一致，函数外层范围相同。
3. 校验范围非空、计数为非负安全整数，拒绝重复区间和交叉重叠。嵌套与相邻区间可以保留。
4. 收集各场景所有边界，排序得到互不重叠的原子区间。
5. 每个场景选择完全包含当前原子区间的最窄范围，继承其 count；找不到范围则拒绝，不能补零。
6. 累加各场景 count，同时单独累加函数外层执行次数，检查安全整数溢出。

结果是覆盖范围的分段表示，不重新生成一棵原始 V8 区间树。该算法只针对本轮经过映射、完整保留的指定函数范围；不处理未知脚本、省略函数、源码转译、source map 或来自不同采集策略的 payload。

## 实际分段与计数

本机 choose 范围为 `[93,180)`。两个场景边界合起来是 93、135、153、179、180，对应合并计数 2、1、1、2。正数 return 的位置 135 与非正数 return 的位置 156，分别落在计数 1 的区间。

| 对照 | baseline | expanded | 合并 |
|---|---|---|---|
| 正数 return 位置 count | 1 | 0 | 1 |
| 非正数 return 位置 count | 0 | 1 | 1 |
| double 外层 count | 1 | 2 | 3 |
| choose 外层 count | 1 | 1 | 2 |
| unused 外层 count | 0 | 1 | 1 |

两个场景的指定分支位置覆盖各为 1/2，合并为 2/2；指定函数覆盖从 baseline 2/3、expanded 3/3 合并为 3/3。比例由实际正计数记录计算，不固定在 report 中。

合并覆盖集合是并集，执行计数是求和，二者不同：重复纳入同一捕获会错误增加次数，即使覆盖率比例不变。实验因此拒绝重复 capture ID，并验证调换场景顺序不改变结果。ID 去重依赖调用方如实标识捕获，不能阻止有人用新 ID 重命名同一 payload；没有实现跨调用持久化去重。

## 与静态语义图的关系

两个场景使用相同 static Evidence 和三个 function 节点；运行计数由调用方覆盖率提供，静态节点不变。跨场景汇总不赋予静态 calls 边新的运行时 authority，也不证明每条静态路径都执行过。

分支观测位置取自自建源码两个不同 return 语句，并按 UTF-16 索引查询合并分段。它验证此 fixture 的两条分支路径有执行，不能推广为全应用分支覆盖率、全部输入覆盖或业务正确性。本轮没有把 ranges 数量当作分支总数，也没有计算注释/空白计数占比冒充分支覆盖。

## 验证与下一步

通过真实 baseline/expanded 采集、三函数累计计数、两个分支位置交替与并集，以及顺序不变验证。对记录的受控变异验证四种拒绝：重复 ID、不同摘要、缺失函数、交叉区间。摘要负例没有执行新版本目标，只验证合并边界拒绝规则。

已保留原始数据与静态 Evidence 引用，生成文件不提交。下一轮可用真正修改过的源码目标验证跨版本拒绝，或实现基于 AST 的分支 inventory，显式处理缺失/部分覆盖与异常路径，避免将本轮两项探针扩展成未经验证的通用算法。
